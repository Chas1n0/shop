# Chase McDougall — clothing shop

Your original link homepage and profile image, plus a clothing storefront and private manager area. Built for Netlify without Shopify. **No live products or payment credentials are included. Checkout starts disabled.**

## Pages

- `/` — original homepage, with the new Shop button.
- `/shop/` — products, sizes/colors, shopping bag, shipping/return/privacy details, and Stripe-hosted checkout.
- `/shop/admin/` — manager login, product drafts/publishing, cover-image uploads, size/color inventory, paid orders, billing and shipping addresses, tracking notes, and shop settings.

Product, order, image, and session data live in site-wide Netlify Blobs and survive redeploys. Non-production deployments have separate storage. There are no hardcoded/demo products. New stores show an honest empty collection until you publish a product.

## Deploy to the existing Netlify site

1. Put this folder's **contents**, including `netlify.toml`, `package.json`, `package-lock.json`, `public`, `lib`, `scripts`, and `netlify/functions`, at the root of `Chas1n0/shop`. Do not upload `.env`, `.netlify`, `node_modules`, or testing credentials. If using GitHub's web uploader, add the code folders and root files; a ZIP sitting in the repository is not a working website.
2. In the **existing Netlify project for chasemcdougall.com**, connect its production deployment to `Chas1n0/shop`, branch `main`. Keep the existing domain assignment and DNS.
3. Build settings: base directory blank, build command `npm run build`, publish directory `public`, functions directory `netlify/functions`. The included `netlify.toml` supplies these settings.
4. Configure the private environment variables below in Netlify for the **production** context, then deploy. Do not put secrets in GitHub. Use your preferred canonical domain for `SITE_URL`; redirect `www` to that hostname in Netlify.
5. Visit `/shop/admin/`, sign in, set your shop details and shipping/return policies, and add your own products. Only products with Publish checked appear publicly. Stock means available inventory; pending checkouts reserve their quantity.

**Do not use Netlify's simple drag-and-drop static deploy for this project.** The shop requires bundled serverless functions and installed dependencies. Use the connected Git repository, or a Netlify CLI deployment that builds/packages functions.

## Manager credentials

Install Node.js 22 or newer and run:

```sh
npm ci
npm run password
```

The password command hides your input and generates `MANAGER_PASSWORD_HASH` and `SESSION_SECRET`. Save them privately in Netlify, along with `MANAGER_EMAIL` and `SITE_URL`. The actual password stays with you. Login is not enabled until these are configured.

| Variable | Purpose |
| --- | --- |
| `SITE_URL` | `https://chasemcdougall.com` (canonical origin, without `/shop`) |
| `MANAGER_EMAIL` | Your chosen manager email; separate from customer support email |
| `MANAGER_PASSWORD_HASH` | Output from `npm run password` |
| `SESSION_SECRET` | Random secret generated by the same command; at least 32 characters |
| `STRIPE_SECRET_KEY` | Private Stripe server/restricted key; never a publishable key |
| `STRIPE_WEBHOOK_SECRET` | Signing secret for this deployment's Stripe event destination |

Manager sessions use encrypted, HttpOnly, Secure, SameSite=Strict cookies, expire in 8 hours, and are revoked on sign-out. Login attempts are rate limited. Manager writes require a matching Origin and a valid server-checked session. There is no public signup or password reset endpoint. To change the manager password, rerun the command, update both generated values in Netlify, and redeploy; this invalidates existing cookies.

## Stripe setup and test order

Use your own Stripe account. Begin with a Stripe sandbox and its server credentials; never test with a real customer's card. The connected Advantage Outreach LLC sandbox can be used, but this source contains no account keys and has not run a real Stripe checkout.

1. Configure a restricted server key with the permissions needed to **create/read Checkout Sessions** (and the resources Stripe requires for inline price/product/shipping creation). If you use a standard secret key while testing, keep it server-side in Netlify. No key belongs in browser code.
2. Create a Stripe event destination for `https://chasemcdougall.com/api/shop/webhook` and subscribe to:
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
   - `checkout.session.expired`
   - `checkout.session.async_payment_failed`
3. Save its signing secret as `STRIPE_WEBHOOK_SECRET` and redeploy. Sandbox and live destinations use different signing secrets.
4. In the manager settings, add a support email, shipping charge, countries, shipping policy, and return policy. Then enable checkout. Currency is USD. Shipping is a single flat charge per order, including zero for free shipping.
5. Create a test product with stock, buy it with Stripe's documented sandbox card details, and confirm the signed event reaches Netlify. Verify the paid order, correct size/color/quantity, billing address, shipping address, total, and stock in the manager.
6. Try a canceled/expired session and verify stock is restored. Checkout reservations last about 30 minutes; closing the browser does not instantly release them. Expiration/failure events release inventory exactly once.
7. Enable **successful-payment email notifications** in your Stripe account notification settings so you receive alerts away from the manager. Configure customer receipts in Stripe as desired. This project does not run a separate email delivery service and does not automatically email tracking updates.
8. Activate your Stripe live account and confirm the products are supported by your account. Change to the live server key and live webhook signing secret, redeploy, and perform your final live verification. Never ship orders labeled TEST ORDER.

Paid-order recording is based on **verified Stripe webhooks**, not the success-page URL. Browser prices are ignored; totals come from saved products. Inventory reservations and orders are updated together using strong reads and conditional atomic writes. Duplicate payment/expiry events do not charge or adjust stock twice. After payment, the shipping/billing information is private to the manager; this site never stores card numbers.

Refunds, disputes, tax registrations, shipping labels, and carrier delivery notifications are managed outside this app. **Automatic sales-tax collection is not enabled.** Confirm and configure any tax collection required for your sales before opening checkout in affected locations. The manager provides fields for your actual shipping and return terms; it does not invent those policies.

## Fulfilling orders

Open Orders and refresh to see new paid orders. Pack the listed items, ship to the saved shipping address, enter the carrier/tracking number, and check Marked as shipped. Billing addresses are shown separately. Test orders are clearly labeled.

For pending orders, **Check payment status** asks Stripe for the current session status and safely records a paid order or releases an expired reservation. If a rare network/storage failure occurs before the session ID is saved, the signed Stripe webhook can still recover the order via its `order_id` metadata. If that order remains pending without a session ID, check Stripe for the full order ID before manually adjusting available inventory. Do not blindly release it: the customer may have paid. A declined card can be retried within the same checkout session; it does not immediately release that reservation.

## Cost and limits

No Shopify subscription or separate database subscription is required by this code. Netlify hosting/functions/Blobs remain subject to your plan's usage allowances and storage charges; free service is not guaranteed indefinitely. Stripe processing fees apply. The single-record store is designed for a small, low-traffic shop. A larger catalog/order history should migrate to a relational database with retention, backups, and operational monitoring.

## Development and verification

```sh
npm ci
npm test
npm run build
```

To run locally, copy `.env.example` to `.env`, set local-only manager credentials and `SITE_URL=http://localhost:8888`, and run `npx netlify dev --offline --no-open --port 8888 --dir public --framework '#static'`. Use localhost so the secure manager cookie can work. Netlify Dev uses its local sandboxed Blobs store.

`tests/domain.test.mjs` covers authoritative server totals, stock reservations and releases, payment validation and idempotency, concurrent purchases, input safety, credentials, and Origin checks. `scripts/integration-check.mjs` is an additional local developer smoke harness that requires generated local test credentials in ignored `.env` and a password in `/tmp/chase-shop-test-password`; it is not a production setup command. It tests the actual Netlify Dev functions and local Blobs service, login/logout, product publishing, uploads, authorization, and stale-write protection.

Local integration checks do not verify live Netlify account configuration, real Stripe payments, external payment notification delivery, or domain routing. Those require the deployment/account setup above. No browser screenshot review has been performed in this environment.
